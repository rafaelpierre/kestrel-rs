  perfectly isolated before/after measurements.

## Decisions

- Keep Python as a frozen compatibility baseline rather than backporting every
  Rust optimization.
- Maintain three benchmark tracks: Python/Rust parity with optimizations off,
  Rust default versus Rust optimization ablations, and Codex Web Search versus
  production-configured Rust Kestrel.
- Use cold-cache measurements as the primary comparison and report warm-cache
  repeated workloads separately.
- Treat fetch budgets as an explicit latency/quality tradeoff.
- Deduplicate by canonical URL before fetching. Content fingerprints are a
  later second-stage defense for mirrors and syndicated copies; hashing URLs
  alone would not improve correctness and is unnecessary for in-memory keys.

## Provider quorum and continued ablation work

- Added opt-in quorum-based fanout completion with `--provider-quorum N` and
  `SearchOptions::provider_quorum`. A provider counts toward the quorum only
  when it returns non-empty results, so fast failures cannot prematurely end a
  search. Defaults continue to wait for every provider.
- Fanout quorum is evaluated independently per query. Completed buckets retain
  configured engine ordering; unfinished provider futures are dropped and the
  cancellation count is exposed through `SearchReport` and benchmark artifacts.
- Confirmed the source of the observed tail: provider requests use a 15-second
  per-attempt timeout, three attempts, and jittered exponential retry delays,
  producing roughly 47-second stragglers.
- A live three-provider search with quorum 2 completed search in 715 ms from
  Bing and Yahoo and cancelled the remaining provider, instead of waiting for
  its retry tail.
- Added a paired Rust pre-ranking ablation harness reporting latency phases,
  provider/fetch diagnostics, requests, bytes, content size, and URL overlap.
  It supports the provider quorum so pre-ranking can be evaluated without one
  throttled provider dominating every sample.
- Completed 24 paired pre-ranking samples (eight queries, three trials) with a
  two-of-three provider quorum. Pre-ranking won 13/24 latency pairs; its paired
  median latency delta was -6 ms and mean delta was -13 ms. Baseline/pre-rank
  p50 elapsed time was 1,690/1,691 ms and p95 was 2,943/2,644 ms.
- Pre-ranking reduced aggregate requests from 294 to 287 and downloaded bytes
  from 58.1 MB to 55.4 MB in this live run. Median returned-character delta was
  zero (mean -15), while final URL overlap had mean Jaccard 0.776 and median
  0.833. These network-sensitive results do not establish semantic quality, so
  `--pre-rank` remains opt-in pending a task-answer evaluation.

## Codex Web Search comparison with quorum and pre-ranking

- Repeated the eight-task, three-trial Codex comparison contemporaneously for
  native Codex Web Search and Rust Kestrel configured with three-provider
  fanout, `--provider-quorum 2`, and `--pre-rank` (24 trials per arm).
- Both arms completed and semantically passed 21/24 trials. Native averaged
  7.38/8; Kestrel averaged 7.29/8. Kestrel's three failures repeated the PyPI
  synthesis mistake of substituting mandatory `id-token: write` for the
  strongly recommended GitHub Environment, even though retrieved material
  contained the needed term. Native's three failures treated Python 3.15 as
  the future main-branch development release instead of Python 3.16.
- Kestrel was faster in 18/24 matched pairs. End-to-end p50 was 15,600 ms
  versus 21,618 ms for native (28% lower); p95 was 28,766 ms versus 44,301 ms
  (35% lower). Median paired delta was -2,674 ms.
- Kestrel median total tokens were 31,371 versus 64,104 for native. Excluding
  cached input and including output/reasoning, the medians were 7,114 versus
  17,810 tokens (60% lower).
- Kestrel retrieval p50/p95 was 1,713/2,810 ms, versus 1,944/3,941 ms in the
  earlier wait-for-all Rust fanout run. Every new trial reached quorum and
  cancelled one of its three provider searches. Returned content remained
  stable at a median 8,431 characters versus 8,417 previously.
- The earlier Rust fanout arm passed 21/24 at 7.46/8. Because the combined
  pre-rank/quorum arm did not improve semantic score, snippet pre-ranking stays
  opt-in. The run is network-sensitive and combines two options, so it is not
  treated as a clean causal estimate of either option alone.
- Final BM25 scores ranged from 0.28 to 8.46 (median 4.03), but decisive
  official pages sometimes scored below less useful pages. A fixed absolute
  minimum would therefore risk deleting needed evidence and would not fix the
  observed PyPI synthesis failure. Any threshold experiment should first emit
  snippet scores, use a relative-to-best gate, retain a minimum result floor,
  and preserve provider/query diversity.
